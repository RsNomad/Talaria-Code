**Outcome (task R1-8b, WS-R1):** `confinedOpen.ts`'s and `rootResolution.ts`'s duplicate `isWithin` predicates are gone. `confinedOpen.ts` (`readContained`'s post-O_PATH-pin containment re-check, ~:153) now imports and calls the canonical `pathConfine.isWithin` (exported by R1-8a) instead of its own local `!rel.startsWith('..')` copy; `rootResolution.ts`'s `isPathWithin` is now `import { isWithin } from '../backend/acp/pathConfine'; export { isWithin as isPathWithin };` — a re-export under its historical name, not a duplicate body — and its former "not a security boundary, kept local" doc is retired in favour of "this IS the canonical function." `resolveRootCoordinator`'s sole caller is unchanged (same signature, same call site). `pathConfine.ts` is **0-diff in this commit** — R1-8a already exported `isWithin`; this task only re-points the two extra copies at it.

The local copy was WEAKER than the canonical one: `!rel.startsWith('..')` denies any in-workspace name merely BEGINNING with `..` (a directory literally named `..cache`, `..x`, etc.), not just a genuine `..`/`../`-prefixed escape. ## ADR-025-D — CA-16 outcome (R2-1, WS-R2)

**Outcome (task R2-1, WS-R2):** `handleRecheck`'s agent-probe section (the `scope === 'all' || scope === 'agent'` branch) now runs its `locatePipx` call under a `'recheck'`-keyed latch, mirroring `handleInstall`'s exact `arm`/`try`/`finally { release }` pattern. Before this task, that branch fired `await this.deps.locatePipx()` with no signal and no latch entry — `dispose()`'s `this.latches.abortAll()` (`:732`) had nothing to reach, so the probe outlived teardown and a late resolve could still write `this.lastAgentIssue`. `latchRegistry.ts` is **0-diff** — `arm(key): AbortController | undefined` already returned the controller (critic I-18); this task only calls it under a new key.

A recheck that arrives while an agent probe is already in flight **coalesces** onto it instead of refusing or re-arming: `if (!this.latches.has('recheck'))` guards the arm/probe/release block, so a concurrent call skips straight through to the method's existing single completion `bumpStatus()` + `{ ok: true }`. This is deliberate, not an oversight — a second `arm('recheck')` would overwrite the `Map` entry under the same key, orphaning the first `AbortController` so `dispose()` could never reach it again (the exact hazard this task closes, reintroduced). Recheck is a read-only status refresh, so refusing the second caller with `{ ok: false }` would surface a spurious error for a panel that just asked to repaint; coalescing is honest because the in-flight probe already covers the agent state the second call asked for. The latch is scoped to the agent-probe section only (not the whole method) — a concurrent `scope: 'all'` recheck still runs its `os`/`llamacpp` rekick work above the guarded block untouched. On dispose (`arm` returns `undefined`), `handleRecheck` returns `{ ok: false, reason: SETUP_DISPOSED_REFUSAL }` immediately, without probing.

**Proof (`SetupController.test.ts`, describe `"R2-1 (L2-CA-16): setup.recheck {scope:'agent'} probes under a 'recheck'-keyed latch"`):** (1) **cancel-on-dispose** — a scripted `locatePipx` captures the signal it receives; before the fix it is `undefined` (RED: `expected undefined to be an instance of AbortSignal`); after the fix, `dispose()` flips the captured signal's `.aborted` to `true`, and the probe's late resolve (after dispose) fires zero `onStatusChanged` events. (2) **single-flight** — two overlapping `{scope:'agent'}` rechecks against a `locatePipx` that never resolves on its own: before the fix, the second call re-arms and calls `locatePipx` again, so the second call's `await` depends on a promise the test never resolves and the test times out (5000ms) reproducing the orphaned-controller deadlock directly; after the fix, `locatePipx` is called exactly once and the second call resolves `{ ok: true }` immediately without waiting on the in-flight probe. All pre-existing recheck goldens (`'setup.recheck re-probes pipx'`, the T6 scoped-recheck suite, `TC-6` dispose suite, `F2-16` disposed-refusal suite) are unchanged (0 edits) and green — none of them exercises overlapping rechecks, so none pinned a whole-method refusal that this design would have had to reconcile against.

**Mutation-proven:** (i) passing `undefined` instead of `abort.signal` into `locatePipx` reproduces the cancel-on-dispose RED (`capturedSignal` stays `undefined`); reverting restores GREEN. (ii) dropping the `if (!this.latches.has('recheck'))` guard (replaced with `if (true)`) reproduces the single-flight timeout — the second call re-arms and re-probes, orphaning the first controller; reverting restores GREEN. Both mutations were applied, run, and reverted; `git diff` against a pre-mutation backup showed zero drift after restore.

No hit for the literal string `'recheck'` anywhere in the pre-task tree, and neither `pullGate.test.ts` nor `pullLatchUnify.test.ts` enumerates the full latch-key set (both are scoped to `install:`/`pull:` prefixes only) — no drift-lock could fail on the new `'recheck'` key, so none needed reconciling.

**R2-1-fix (review Minor, coalesce-window closure):** R2-1's review left ONE Minor: `this.hermesDiscoveryMemo.invalidate()` sat *inside* the `if (!this.latches.has('recheck'))` guard, so a **coalescing** recheck (the second, overlapping call) skipped it — only the in-flight call's own `invalidate()` ever ran. Grounding confirmed `SettledProbeMemo.invalidate()` (`settledProbeMemo.ts`) is a cheap, idempotent epoch bump that clears `settled`/`inFlight` and does not touch `locatePipx`, the `'recheck'` latch, or (for this memo, constructed with `cancellable: false`) any in-flight probe's `AbortController` — safe to call unconditionally, including after `dispose()`'s `supersede()`. The fix hoists the single `this.hermesDiscoveryMemo.invalidate()` call to run ONCE per `handleRecheck` invocation, **above** the `if (!this.latches.has('recheck'))` guard (still inside the `scope === 'all' || scope === 'agent'` block), and removes the now-duplicate call from inside the guard/`try`. The `locatePipx` arm/probe/release — the CA-16 single-flight core — is untouched: still exactly one `locatePipx` call for two overlapping rechecks.

This closes a real (if narrow) race: a `status()` poll landing between an in-flight recheck's `invalidate()` and its `locatePipx` settle can re-kick `hermesDiscoveryMemo` and re-settle it with a now-stale value; before this fix, a coalescing second recheck left that stale value untouched (its own `invalidate()` lived inside the never-entered guard), so the panel could still read "hermes not found" for one extra Re-check click after the user actually installed it. After the fix, the coalescing call's hoisted `invalidate()` clears the stale re-kicked value too, so the very next `status()` re-probes fresh.
