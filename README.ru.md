## Что такое Talaria Code?

Talaria Code встраивает **агентного ИИ-ассистента для кода** в нативную боковую
панель VS Code — чат, многошаговые правки с вашим подтверждением, вызов
инструментов и ответы с учётом вашего кода — и всё это работает на моделях,
которые **вы** держите у себя через **Ollama**, **vLLM** или **llama.cpp**. Это
клиент агента [Hermes](https://github.com/nousresearch/hermes-agent), построенный по принципу local-first: ваш код и запросы
идут на те эндпоинты моделей, которыми управляете *вы*, а не в чужое облако.

Если вам нужны удобства современного ИИ-ассистента, но без отправки исходного
кода стороннему сервису — это для вас.

## Возможности

- 💬 **Агентный чат** — агент для кода в нативной панели VS Code, со вкладками и историей сессий.
- ✍️ **Правки с подтверждением** — каждое изменение файла *предлагается* и ждёт вашего явного «да/нет». Ничего не пишется молча.
- ⚡ **Автодополнение + Next Edit** — дополнение по типу fill-in-the-middle (FIM) и подсказки следующей правки на ваших локальных моделях.
- 🔎 **С учётом кодовой базы** — локальный RAG-индекс (LanceDB + tree-sitter): ответы опираются на *ваш* реальный код.
- 🧩 **Инструменты и MCP** — подключение серверов [Model Context Protocol](https://modelcontextprotocol.io) и доступ агента к «умному» анализу редактора (диагностика, определения, ссылки).
- 🕘 **Чекпоинты** — снимок и восстановление состояния воркспейса вокруг ходов агента.
- 🔒 **Приватность по умолчанию** — исходящее содержимое сканируется на секреты перед отправкой; подтверждения работают по принципу «fail-closed»; агент ограничен воркспейсом.

## Приватность и безопасность

Это и есть суть Talaria Code, а не что-то второстепенное:

- **Сканирование исходящего.** Всё, что идёт к модели, сначала сканируется;
  секреты и файлы, похожие на учётные данные, вырезаются или блокируются до
  отправки.
- **Подтверждение по принципу «fail-closed».** У запросов на разрешение есть
  дедлайн — отсутствие ответа в окне трактуется как **запрет**, а не как молчаливое
  согласие.
- **Ограничение воркспейсом.** Доступ к файлам и правки ограничены вашим
  воркспейсом; попытки выйти за пределы (`..`, абсолютные системные пути)
  отклоняются.
- **Настройки моделей на уровне машины.** С каким бэкендом и моделью вы
  общаетесь — настройка уровня машины: открытый воркспейс не может молча
  переключить агента на другой эндпоинт.

> **Честная формулировка:** Talaria Code — *local-first*: каждый эндпоинт модели,
> эмбеддингов и MCP настраиваете и держите вы. Это **не** жёсткая гарантия, что с
> машины никогда не уходит ни байта (вы можете указать удалённый узел, которым
> владеете сами, или подключить удалённый MCP-сервер). Цель дизайна — чтобы
> **вы** контролировали каждый адрес назначения, а секреты в любом случае
> вырезались из потока.

## Требования

| Требование | Примечания |
|---|---|
| **VS Code** | `^1.125` |
| **ОС** | Основная цель — **Linux**. Mock-интерфейс работает где угодно, но живой бэкенд рассчитан на Linux; остальные платформы пока не тестировались. |
| **Агент Hermes** | Бэкенд, которым управляет Talaria Code (`hermes acp` + `python -m tui_gateway.entry`). Расширение — это *клиент* Hermes. |
| **Локальный раннер моделей** | **Ollama**, **vLLM** или **llama.cpp**, обслуживающий: чат/агентную модель (через Hermes), FIM-модель для автодополнения (по умолчанию `qwen2.5-coder:1.5b-base`) и модель эмбеддингов для RAG (по умолчанию `qwen3-embedding:0.6b`). |

## Установка

Talaria Code пока нет в Marketplace. Соберите и установите из исходников:

```bash
npm install        # host + webview (npm workspaces)
npm run build      # сборка обоих бандлов
npm run package    # создать .vsix через vsce

code --install-extension talaria-code-*.vsix
```

## Быстрый старт

1. Установите и запустите агент **Hermes** и **раннер моделей** (например, Ollama
   с моделями выше).
2. Откройте панель **Talaria** на боковой панели активности.
3. Укажите расширению путь к вашей установке Hermes и переключите
   `talaria.backend` с `mock` на `acp` (см. «Настройка»).

При первом запуске используется сценарный **mock**-бэкенд, чтобы можно было
изучить интерфейс без запущенного процесса Hermes — он работает на любой ОС.
Переключитесь на `acp`, чтобы работать вживую с реальным агентом.

## Настройка

Настройки живут в неймспейсе **`talaria.*`** (Talaria Code — клиент Hermes). Те,
что нужны чаще всего:

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `talaria.backend` | `mock` | С каким бэкендом общаться. Поставьте `acp` для реального бэкенда Hermes. |
| `talaria.hermesPath` | `""` | Абсолютный путь к исполняемому файлу `hermes`. |
| `talaria.pythonPath` | `""` | Интерпретатор Python для запуска реального бэкенда Hermes. |
| `talaria.cwd` | `""` | Рабочая директория агента (по умолчанию — первая папка воркспейса). |
| `talaria.autocomplete.enabled` | `true` | Включить встроенное (FIM) автодополнение. |
| `talaria.autocomplete.backend` | `ollama` | Бэкенд, обслуживающий автодополнение. |
| `talaria.autocomplete.model` | `qwen2.5-coder:1.5b-base` | Модель для автодополнения. |
| `talaria.autocomplete.endpoint` | `""` | Базовый URL бэкенда автодополнения (может быть вашим узлом). |
| `talaria.rag.enabled` | `true` | Включить RAG-индекс кодовой базы и поиск. |
| `talaria.rag.embedEndpoint` | `http://127.0.0.1:11434` | Базовый URL бэкенда эмбеддингов. |
| `talaria.rag.embedModel` | `qwen3-embedding:0.6b` | Модель для эмбеддинга фрагментов кода. |

Полный набор — в UI настроек (поиск по `talaria`).

## Как это устроено

```
VS Code  ──►  Talaria Code (это расширение)
                   │  Agent Client Protocol (ACP)
                   ▼
              Агент Hermes  ──►  ваш локальный раннер моделей
                                 (Ollama / vLLM / llama.cpp)
```

Два бандла, один репозиторий: **host** на TypeScript (esbuild → `dist/extension.js`)
и панель-**webview** на React 18 (Vite → `dist/webview/`). Они общаются по единому
типизированному протоколу `postMessage` — webview никогда не трогает Node или API
VS Code напрямую. Host управляет агентом Hermes по ACP для чата, правок,
инструментов и MCP; автодополнение и эмбеддинги кода ходят **напрямую** на
эндпоинты моделей, которые вы настроили.

## Разработка

Требования: Node ≥ 18 (рекомендуется Node 24), VS Code ≥ 1.125.

```bash
npm install
```

Нажмите **F5** в VS Code — соберутся оба бандла и откроется Extension Development
Host с mock-данными; процесс Hermes не запускается, поэтому работает на любой ОС.

| Скрипт | Что делает |
|---|---|
| `npm run build` | Собрать оба бандла один раз |
| `npm run watch` | Пересобирать оба бандла при изменениях |
| `npm run check-types` | Проверка типов `tsc --noEmit` для `src/**` |
| `npm run package` | Создать `.vsix` через `vsce` |
