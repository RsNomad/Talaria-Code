## Что такое Talaria Code?

Talaria Code встраивает **агентного ИИ-ассистента для кода** в нативную боковую
панель VS Code — чат, многошаговые правки с вашим подтверждением, вызов
инструментов и ответы с учётом вашего кода — и всё это работает на моделях,
которые **вы** держите у себя через **Ollama**, **vLLM** или **llama.cpp**. Это
клиент агента [Hermes](https://github.com/nousresearch/hermes-agent), построенный по принципу local-first: ваш код и запросы
идут на те эндпоинты моделей, которыми управляете *вы*, а не в чужое облако.

Если вам нужны удобства современного ИИ-ассистента, но без отправки исходного
кода стороннему сервису — это для вас.

## Возможности

- 💬 **Агентный чат** — агент для кода в нативной панели VS Code, со вкладками и историей сессий.
- ✍️ **Правки с подтверждением** — каждое изменение файла *предлагается* и ждёт вашего явного «да/нет». Ничего не пишется молча.
- ⚡ **Автодополнение + Next Edit** — дополнение по типу fill-in-the-middle (FIM) и подсказки следующей правки на ваших локальных моделях.
- 🔎 **С учётом кодовой базы** — локальный RAG-индекс (LanceDB + tree-sitter): ответы опираются на *ваш* реальный код.
- 🧩 **Инструменты и MCP** — подключение серверов [Model Context Protocol](https://modelcontextprotocol.io) и доступ агента к «умному» анализу редактора (диагностика, определения, ссылки).
- 🕘 **Чекпоинты** — снимок и восстановление состояния воркспейса вокруг ходов агента.
- 🔒 **Приватность по умолчанию** — исходящее содержимое сканируется на секреты перед отправкой; подтверждения работают по принципу «fail-closed»; агент ограничен воркспейсом.

## Приватность и безопасность

Это и есть суть Talaria Code, а не что-то второстепенное:

- **Сканирование исходящего.** Всё, что идёт к модели, сначала сканируется;
  секреты и файлы, похожие на учётные данные, вырезаются или блокируются до
  отправки.
- **Подтверждение по принципу «fail-closed».** У запросов на разрешение есть
  дедлайн — отсутствие ответа в окне трактуется как **запрет**, а не как молчаливое
  согласие.
- **Ограничение воркспейсом.** Доступ к файлам и правки ограничены вашим
  воркспейсом; попытки выйти за пределы (`..`, абсолютные системные пути)
  отклоняются.
- **Настройки моделей на уровне машины.** С каким бэкендом и моделью вы
  общаетесь — настройка уровня машины: открытый воркспейс не может молча
  переключить агента на другой эндпоинт.

> **Честная формулировка:** Talaria Code — *local-first*: каждый эндпоинт модели,
> эмбеддингов и MCP настраиваете и держите вы. Это **не** жёсткая гарантия, что с
> машины никогда не уходит ни байта (вы можете указать удалённый узел, которым
> владеете сами, или подключить удалённый MCP-сервер). Цель дизайна — чтобы
> **вы** контролировали каждый адрес назначения, а секреты в любом случае
> вырезались из потока.

## Требования

| Требование | Примечания |
|---|---|
| **VS Code** | `^1.125` |
| **ОС** | Основная цель — **Linux** (разработка на Fedora). Mock-интерфейс работает где угодно, но живой бэкенд рассчитан на Linux; остальные платформы пока не тестировались. |
| **Python + pipx** | Python **3.11–3.13** и **pipx** в вашем `PATH`. Панель **Backend Setup** сама установит агент Hermes через pipx — расширение остаётся *клиентом* Hermes. На Fedora: `sudo dnf install pipx`. |
| **Локальный раннер моделей** | **Ollama**, **vLLM** или **llama.cpp**, обслуживающий: чат/агентную модель (через Hermes), FIM-модель для автодополнения (по умолчанию `qwen2.5-coder:1.5b-base`) и модель эмбеддингов для RAG (по умолчанию `qwen3-embedding:0.6b`). Ollama можно обнаружить и скачать её модели прямо из панели Setup. |

## Установка

Talaria Code пока нет в Marketplace. Соберите и установите из исходников:

```bash
npm install        # host + webview (npm workspaces)
npm run build      # сборка обоих бандлов
npm run package    # создать .vsix через vsce

code --install-extension talaria-code-*.vsix
```

## Быстрый старт

Talaria Code устанавливает и настраивает свой бэкенд из **одной панели** — без
ручного редактирования JSON и без ручной установки Python.

1. **Установите расширение** (`.vsix` — см. [«Установка»](#установка)).
2. **Откройте панель Talaria** на боковой панели активности. При первом запуске
   **Backend Setup** открывается автоматически. Открыть её снова можно в любой
   момент — значком **ракеты** в заголовке панели или командой
   **`Talaria: Backend Setup`**.
3. **Пройдите пять карточек** — у каждой свой статус, одно основное действие и
   раскрываемый лог:
   - **Agent** — выберите **Hermes** и нажмите **Install Hermes**. Панель
     установит `hermes-agent[acp]` через pipx, проверит установку, пропишет пути
     и предложит перезагрузку окна в один клик, чтобы перейти вживую. (OpenClaw и
     Talaria AI показаны как *coming soon*.)
   - **Provider** — нажмите **Configure provider**, чтобы запустить собственный
     мастер настройки Hermes в терминале и выбрать чат-модель/провайдера для
     агента. Talaria никогда не навязывает вам провайдера.
   - **Autocomplete (FIM)** — выберите бэкенд (Ollama / llama.cpp / vLLM /
     Codestral / OpenAI-совместимый). Для локальных бэкендов карточка спрашивает
     **«Установить локально или подключиться к существующему эндпоинту?»** Для
     Ollama можно обнаружить демон и скачать модель по умолчанию
     (`qwen2.5-coder:1.5b-base`) с индикатором прогресса.
   - **Next Edit** *(опционально)* — многострочные подсказки следующей правки.
     **Generic** переиспользует уже настроенную FIM-модель (без доп. настройки);
     **Dedicated** использует отдельную модель, которую вы настраиваете здесь.
   - **Codebase index (RAG)** *(опционально)* — включите локальный индекс кода и,
     на Ollama, скачайте модель эмбеддингов (`qwen3-embedding:0.6b`).

Пока вы не установили реальный бэкенд, расширение использует сценарный
**mock**-бэкенд, чтобы можно было изучить интерфейс без запущенного процесса
агента — он работает на любой ОС.

### Честные оговорки

- **Python и pipx — реальные предпосылки.** Панель не может выполнить `sudo` за
  вас: на Fedora сначала выполните одну подсказанную команду
  `sudo dnf install pipx`. Hermes требует Python **3.11–3.13**.
- **Установка Hermes скачивает ≈300–500 МБ** с PyPI в `~/.local/share/pipx`.
- **Модели весят гигабайты и зависят от железа.** FIM-модель ≈1 ГБ, эмбеддинги
  ≈0.7 ГБ, а чат-модель агента может быть намного больше. Размеры показываются
  до любой загрузки, и ничего не скачивается автоматически — один клик упрощает
  *клики*, но не уменьшает загрузки и не создаёт GPU.
- **Локальные установки llama.cpp/vLLM — сопровождаемые, а не безмолвные.** У
  Ollama это чистая установка одним скриптом; llama.cpp и vLLM требуют ваших
  решений по сборке/железу, и карточки об этом говорят. «Один клик» означает, что
  мы открываем нужную команду в терминале и автоматизируем всё после неё
  (скачивание, настройка, проверка).
- **Перезагрузка окна активирует агент** при первом включении.

## Настройки

У Talaria Code **один источник истины** для конфигурации — настройки `talaria.*`
VS Code (плюс SecretStorage VS Code для API-ключей). Каждый экран — лишь
представление этого источника, поэтому **ничего не дублируется, и у каждой
настройки ровно один дом.** Есть две поверхности, разделённые по *владельцу
настройки*:

### Talaria Config — собственные настройки расширения

Все ключи `talaria.*`: бэкенд агента и подключение Hermes, автодополнение (FIM),
Next Edit и индекс кодовой базы (RAG). Их можно править двумя равнозначными
способами — оба пишут одни и те же настройки, выбирайте любой:

- **Панель Backend Setup** (дружелюбная): те самые пять карточек.
- **Нативная страница настроек** — команда **`Talaria: Open Settings`** или поиск
  `@ext:syntinal.talaria-code`. Она разбита на пять озаглавленных разделов:
  **Backend & Agent**, **Autocomplete (FIM)**, **Next Edit**,
  **RAG (Codebase Index)** и **Advanced**.

Настройки, которые нужны чаще всего:

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `talaria.backend` | `mock` | С каким бэкендом общаться. Поставьте `acp` для реального бэкенда Hermes (панель Setup делает это за вас). |
| `talaria.hermesPath` | `""` | Абсолютный путь к исполняемому файлу `hermes` (пишет установщик). |
| `talaria.pythonPath` | `""` | Интерпретатор Python для запуска реального бэкенда Hermes (пишет установщик). |
| `talaria.cwd` | `""` | Рабочая директория агента (по умолчанию — первая папка воркспейса). |
| `talaria.autocomplete.enabled` | `true` | Включить встроенное (FIM) автодополнение. |
| `talaria.autocomplete.backend` | `ollama` | Бэкенд, обслуживающий автодополнение. |
| `talaria.autocomplete.model` | `qwen2.5-coder:1.5b-base` | Модель для автодополнения. |
| `talaria.autocomplete.endpoint` | `""` | Базовый URL бэкенда автодополнения (может быть вашим узлом). |
| `talaria.rag.enabled` | `true` | Включить RAG-индекс кодовой базы и поиск. |
| `talaria.rag.embedEndpoint` | `http://127.0.0.1:11434` | Базовый URL бэкенда эмбеддингов. |
| `talaria.rag.embedModel` | `qwen3-embedding:0.6b` | Модель для эмбеддинга фрагментов кода. |

Настройки, которые перенаправляют исполняемый файл или эндпоинт модели, имеют
**scope machine**, поэтому открытый воркспейс не может молча их изменить;
API-ключи живут в SecretStorage VS Code, а не в открытых настройках. Полный набор
— на нативной странице настроек.

### Agent Config — рантайм-настройки агента Hermes

Собственная рантайм-конфигурация Hermes — политика подтверждений, лимит ходов,
делегирование, чекпоинты, безопасность — живёт во вкладке **«Agent config»**
внутри панели Talaria. Это настройки *агента* (его `config.yaml`, правятся по
управляющему каналу), а не настройки расширения `talaria.*` — поэтому у них свой
дом и они не дублируются с поверхностью Talaria Config.

## Как это устроено

```
VS Code  ──►  Talaria Code (это расширение)
                   │  Agent Client Protocol (ACP)
                   ▼
              Агент Hermes  ──►  ваш локальный раннер моделей
                                 (Ollama / vLLM / llama.cpp)
```

Два бандла, один репозиторий: **host** на TypeScript (esbuild → `dist/extension.js`)
и панель-**webview** на React 18 (Vite → `dist/webview/`). Они общаются по единому
типизированному протоколу `postMessage` — webview никогда не трогает Node или API
VS Code напрямую. Host управляет агентом Hermes по ACP для чата, правок,
инструментов и MCP; автодополнение и эмбеддинги кода ходят **напрямую** на
эндпоинты моделей, которые вы настроили.

## Ручная настройка (для продвинутых)

Панель Backend Setup необязательна — всё, что она пишет, это обычные настройки
`talaria.*`, которые можно задать вручную, если хотите настроить всё сами:

1. **Установите агент Hermes сами**, например
   `pipx install "hermes-agent[acp]==0.18.2"` (extra `[acp]` обязателен, иначе
   `hermes acp` падает на импорте), или через собственный установщик Hermes.
2. **Укажите путь расширению**: задайте `talaria.hermesPath` на исполняемый файл
   `hermes` и `talaria.pythonPath` на соответствующий интерпретатор. При
   установке через pipx оба лежат в `~/.local/share/pipx/venvs/hermes-agent/bin/`.
3. **Перейдите вживую**: задайте `talaria.backend` = `acp` и перезагрузите окно.
4. **Настройте чат-модель/провайдера** собственным мастером Hermes:
   `hermes-acp --setup`.
5. **Запустите раннер моделей** (Ollama / vLLM / llama.cpp) и задайте ключи
   `talaria.autocomplete.*` и `talaria.rag.*` на ваши эндпоинты и модели (по
   умолчанию: FIM `qwen2.5-coder:1.5b-base`, эмбеддинги `qwen3-embedding:0.6b`).

## Разработка

Требования: Node ≥ 18 (рекомендуется Node 24), VS Code ≥ 1.125.

```bash
npm install
```

Нажмите **F5** в VS Code — соберутся оба бандла и откроется Extension Development
Host с mock-данными; процесс Hermes не запускается, поэтому работает на любой ОС.

| Скрипт | Что делает |
|---|---|
| `npm run build` | Собрать оба бандла один раз |
| `npm run watch` | Пересобирать оба бандла при изменениях |
| `npm run check-types` | Проверка типов `tsc --noEmit` для `src/**` |
| `npm run package` | Создать `.vsix` через `vsce` |
